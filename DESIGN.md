# Skytumble — Design

An original rolling-block puzzle game: tip a 1×1×2 block across floating sky islands
and drop it upright into the goal hole. Levels are procedurally generated and verified
by a solver. Inspired by the rolling-block genre; its own name, look, and levels.

## Goals

- Built for fun: a game I play myself and introduce to friends.
- Improve on the classic genre: generated levels, scoring against the optimal solution,
  a better camera.
- Stop feeling like a copy. v1 matched the classic games in mechanics, level shapes, and
  loop; all three need to become Skytumble's own.

**Success (six months out):** I still play it; friends come back to it unprompted; side
by side it feels better than the old games; the project keeps growing.

**A new mechanic succeeded** if I choose levels that feature it unprompted, weeks later.

## Decisions

| Area | Decision | Why |
|---|---|---|
| Identity | Original game, **Skytumble**; floating islands, in the sky at first and anywhere later | Own look and name; not a clone |
| Visuals | 3D (Three.js). All art made in code, no model packs (decided 2026-11-01) | One consistent style, nothing to download |
| Platform | Desktop only, keyboard | — |
| Camera | Rotates in 90° snaps; controls are screen-relative (Up = away from you) | No ambiguous diagonals |
| Timing | Turn-based only; anything "timed" counts moves, not seconds | Solver stays exact; par stays meaningful |
| Organization | **Themed biomes** replace difficulty tiers. Each biome starts with one signature mechanic; later biomes mix earlier ones | Gives mechanics a home and an identity |
| Base layer | Floor, fragile, switches, bridges appear in every biome; they are not a biome | They're the grammar every biome builds on |
| Difficulty | Rises with depth: further into a biome, higher in the climb | No separate tier picker |
| Level shapes | Archipelagos: several small islands joined by crossings | Rectangle blobs read as the old games |
| Crossings | Bridges now; teleporters, launch pads, drops/elevators later | Keep each release to 1–2 new mechanics |
| Pace | 1–2 new mechanics per release, each done deeply | Depth over a grab bag |
| Rule changes | Prototype new rules in throwaway "lab" levels; rules freeze after playtest sign-off | Rewriting rules breaks handmade levels |
| Quality guard | ~5 handmade reference levels to judge generator output against | Pre-mortem: "generated levels feel bland" |
| Sharing | Seed links (`?tier=…&seed=…`); old links may change as the generator evolves | Links mean "play this now" |
| Hosting | Static site (GitHub Pages / itch.io), no accounts | Free, nothing to run |
| Tech | Vite + TypeScript + Three.js; generator/solver in a Web Worker | Type safety for logic; UI never freezes |

**"Hard" means:** precise orientation, switch logic, deceptive layouts (routes that
detour away from the goal). Solution length alone is not the target.

## Modes

| Mode | Purpose | Levels | Failure |
|---|---|---|---|
| **Campaign** | Learn: the natural progression for getting better | Handmade, one chapter per biome | Undo always allowed |
| **Endless climb** | Test: the replayable challenge | Generated; altitude bands are biomes | No undo; a fall ends the run; score = altitude |
| Quick play (v1) | Out of the menus until the climb replaces it; `?tier=` links still work | Generated by tier + seed | Undo allowed |

- **Map:** a sky map of biome islands, all open from the start with a suggested path
  (soft order) so friends can jump anywhere.
- **Daily climb:** everyone gets the same run seed each day (derived from the date in the
  browser, no server); friends compare altitudes.
- **Handmade → generated:** campaign levels show what good levels in each biome look
  like; the generator learns each biome from them when the climb is built.

## Mechanics

| Mechanic | Rule |
|---|---|
| Rolling | Block is standing (1×1) or lying (1×2); rolling tips it over an edge |
| Goal | Win by standing upright on the goal; lying across it is safe |
| Falling | Any part of the block over empty space → fall |
| Fragile tile | Breaks if the block stands upright on it |
| Soft switch | Toggles its bridge group when any part of the block lands on it |
| Heavy switch | Toggles its bridge group only when the block stands on it |
| Bridge | Solid only while its group is on. A reversed bridge is the opposite, so one press can trade two bridges |
| Wall | Raised, it stops any roll that would land on it. Lowered, it is plain floor. A press flips every wall and bridge of its color |
| **Ice** (Frost) | A lying block fully on ice slides in the roll direction; a standing block grips |
| **Conveyor** (Frost) | After a move, a block fully on conveyors shifts one tile along the arrow |
| **Launch pad** (Windy Peaks) | Flings the block along the pad's arrow: standing = long fling, lying fully on two same-arrow pads = short hop |
| **Flip tile** (Starfall) | Standing on one, or lying fully on two, moves the block to the other floor directly above (or below), same pose. The landing acts like any landing: pads there fire (allowed 2026-11-19; no existing level changed), but a ring there never flips the block straight back that move |
| **Glass tube** (Toybox; **rules frozen** 2026-11-19 after the user's looks) | The twist: **ice for the cube**, and for longer blocks fed in by belts. A tube runs east-west (`=`) or north-south (`|`); a cube rolling into an open end slides straight through and stops on the first ordinary tile past the far end, and off the end into nothing it falls, as off ice. Any other block bumps a tube, in any pose, and a cube bumps its side, going in or coming out. A raised wall in the tube's line brakes the slide inside the tube, and a lowered one is floor, so the slide ends on it. Belts can also feed a longer block in: lying along the tube and fully on belts (two belts for a 2×1, three for a 3×1), it's pushed in, slides through and shoots out wholly past the far end, onto the two or three tiles beyond (falling if there's no floor); a tube slides a block until it's completely out, where ice stops it half off. A longer block never rolls into a tube (tipping over its edge would pass through it), and belts pushing a block across a tube hold it. The cube glides in and out instead of tipping, and a belt push into a tube glides the block in flat (no lean), so nothing clips the roof. Look: a squared tube of blue plastic panels all round (roof, floor, sides), each with a square glass window, with thick blue edges and end frames (a deeper blue than the blue switch); tubes in a row join into one and need no ground, so they can bridge islands. (Settled over five looks: an arch, a slot and a green cube door came first.) **Stuck inside** (the user's call, 2026-11-20, after a cube braked in `toy-20`'s top tube vanished behind the panels until rolled out): while any part of the block is in a tube tile, that tile's blue panels fade to clear glass, so the block always shows, sliding through or stuck; a slide a raised wall brakes inside a tube ends in a knock (the block rebounds a little off the wall, which shakes); and a bump inside a tube is a short shove against the glass instead of a tip through it. Rules unchanged. For now tubes mix with the basics, shapes, walls and belts only |
| **Splitter** (Splatter Studio; **rules frozen** 2026-11-20 after the Split Lab playtests) | A normal block standing on one splits into two light cubes: one stays, the other pops out on the marked side and moves first; no split toward a gap or a raised wall. Tab swaps which cube moves, free (never a move, never in par). Cubes join only when the moving one rolls into the other, into a lying block over their two tiles. Belts push only the cube that moved; the idle cube stands in the way of slides, pushes and flights like a raised wall, holds a wall down under it, and falls if a press takes its bridge. The goal takes only the whole block. One floor, no hedges, shape switches or marked goals |
| **Paint** (Splatter Studio; **rules frozen** 2026-11-21 after the Paint Lab playtests) | Red, blue and yellow trays coat the part of the block resting on them (a cube all over, a lying block's half, a standing block's bottom half). Coats mix: two primaries make purple, orange or green; a coat on a mix, or a third primary, makes mud. Water strips the resting part bare. A gate lets through only a part exactly its color (a standing block needs both halves in it) and otherwise holds like a raised wall, braking slides and holding belt pushes. Each half keeps its color as the block rolls; a split pops the top half out in its color, a join keeps each cube's color on its half. One floor, no hedges, shape switches, tall blocks or goals, pads or flip rings. Levels rotate their colors |
| **Held switch** (the Chasm; **rules frozen** 2026-11-24 after the Chasm Lab playtests) | A square switch: its color's walls, bridges and rings stay switched only while anything rests on it (a cube, either half of a lying block, a standing block, the idle cube), and switch back the moment it's let go. Checked where the block comes to rest, after any split; a let-go that retracts a bridge drops the block or the idle cube. A wall that comes up under a cube waits until it moves off. One kind per color: a held switch's color has no press switches |
| **Dark tiles and lights** (the Chasm; **rules frozen** 2026-11-24 after the Chasm Lab playtests) | Dark tiles are floor to the rules, unseen in play: each shows only while a block rests on it, and all of a light color show while that color is lit. A timed light switch lights its color for N moves after a press (any rest on it by the moving block), counting every roll of either cube, Tab free; a second press restarts the count. A held light switch lights its color while anything rests on it. A fall beside an unlit dark tile (or from one) rewinds to the moment that light last went out; other falls undo one move. The Hint key shows the dark tiles faintly. A light color is never a switch color in the same level; every dark color has a light and every light dark tiles. Lights may sit on one floor and their tiles on the other. Presentation only: the solver ignores lighting, so a level's lights sit on the best route (lint warns UNSEEN) |
| **Toppling hedge** (First Glade) | A standing block rolling into it topples it that way for good and stays put, for one move. It lands on the next tile, and an empty tile becomes floor. A lying block just bumps it |

**Whole-block rule:** a special tile (ice, conveyor) acts only when the entire block is on
it. A lying block half on ice and half on floor does not slide. A lying block on two conveyors
pointing different ways is not pushed.

**Move resolution:** roll → slide while fully on ice → the slide stops as soon as any part
leaves ice → the tile it rests on acts (a conveyor pushes once per move; if that leaves a
lying block fully on ice, it slides in the push direction) → stop. Falls are checked at
every step. Only resting spots trigger fragile tiles and switches; tiles passed mid-slide
don't. One conveyor push per move means no infinite loops.

**Walls and hedges** (**rules frozen** 2026-11-05 after the Glade Lab playtests):
- *Bump:* a roll is stopped by the first raised wall or upright hedge among the tiles it would land on, nearest the block first. The block stays where it was. That covers the far tile of a standing block's roll, and a wall beyond a gap, where the block would otherwise fall: nothing lands, so nothing falls. A bump isn't a move: no count, no undo step.
- *Hedge:* a standing normal or tall block topples the first hedge in its way, including one two tiles off, along the roll, and stays put. That costs one move, can be undone, and comes back on restart. Lying blocks and the cube only bump it. Only a roll can topple one.
- *Where it lands:* the next tile along the roll. An empty tile becomes floor for good. Anything else solid gets nothing, so that hedge is wasted, including a tile another hedge already bridged, and a retracted bridge's tile, which stays a gap. The hedge's own tile is floor either way.
- *Walls with ice and belts* (Frost Isle; **rules frozen** 2026-11-07 after the Frost Lab playtests): a slide stops on the tile before a raised wall or low stone (a brake), and a wall touching either end of a lying block stops it. A lowered wall is floor, so a slide also stops half on it. A belt can't push into a raised wall: the block stays put (held), and the belt tries again only the next time the block lands on it. Flips and shapes with walls are still unsettled (Starfall and Toybox labs). How To Play's *Walls on ice and belts* entry plays it in one loop: held on a belt by a raised wall, one press lowers it and raises another at the end of the ice, the belt carries the block onto the lowered wall, and the slide brakes before the raised one.
- *What stops it:* a raised wall or a hedge still up on the landing tile. It holds, and that's a bump, not a move. So a line of hedges has to be cleared from the far end or from the side.
- *Colors:* a press flips every wall and bridge of its group. A wall starts up or down on its own, whatever `bridges-on` says, and a reversed bridge is always the opposite of its group's digit bridges.
- *Block on a wall's tile:* a wall that comes up under the block shows lowered until the block moves off. The rules don't need to track this: only a roll into a tile checks for a wall, and a roll never lands on the tiles it left.
- *Walls with launch pads* (Windy Peaks; **rules frozen** 2026-11-09 after the Peaks Lab playtests): flights pass over walls, and only the landing matters. A raised wall or low stone where a fling or a hop along two pads would land stops it short: the block stands up on the tile before the wall (falling if nothing is there, and pressing what's there like any landing). A raised wall on a sideways hop's landing, or a second one on the tile before it, makes the block fall: it hits the wall and drops in front of it. Landing marks follow the walls: the mark sits where a flight stops short, and a flight that would crash marks nothing. The animation differs by jump: a fling comes down hard against the wall and rocks back upright, a hop tips up against the wall's face, a crash bounces back and falls. How To Play's *Walls and launch pads* entry plays it in one loop: a fling stops short, standing before a raised wall; a press on the way back lowers it, and the same fling flies the full way, lying on the lowered wall beside the goal. It opens in any level with walls and pads, first in the campaign at `wind-09`.
- *Switches and flip rings* (Starfall; **rules frozen** 2026-11-19, when the user approved batch 1 without changes; changed the same day at the user's call from walls locking rings across floors, which "seems kind of dumb"): a ring can take a switch color (`M P Q W` starting locked, `m p q w` starting open; a plain `+` never changes). A press of its color opens or locks it, along with that color's walls and bridges. A locked ring won't fire, and the block rests on it like floor; a block lying across two rings flips only if both are open. Walls and rings never share a cell across floors: a wall directly over or under a ring fails validation, so a flip always has somewhere to land. Walls still cross floors like bridges (one switch state per color). The indicator: a colored ring has a thin line of its color around it, like a wall; locked, it goes dull with no glow and a small padlock in its color stands on it, turned to face the camera, and its violet landing mark on the other floor goes away. Resting on a locked ring pops that padlock up over the block, with a shake and a fade, since the ring's own padlock is hidden under it. A locked ring with no switch to open it is decoration, and `lint` warns.
- *Splitting and paint with launch pads* (Splatter Studio's Pad Lab; **rules frozen** 2026-11-22 after the user's playtest): a cube on a pad flies like a standing block, four tiles out. The idle cube where a flight lands is a raised wall (no joining in mid-air), and so is a gate that holds the landing part's color; the walls-with-pads rule then stops the flight short or crashes it. A landing on a tray or water coats or washes like any rest, and a landing standing on a splitter splits. The colors turn with the flight's tip like one roll (a standing fling stopped short lands upright, unturned). Tubes and pads stay apart. Before this, a flight ignored gates and kept its colors unturned; no level had paint with pads, so none changed.
- *Walls with shapes* (Toybox; **rules frozen** 2026-11-19 after the Toybox Lab playtest): the bump rule already covers every shape, since a roll is stopped by any raised wall among the tiles it would land on. A standing tall block is stopped by a wall three tiles off (its tip covers three tiles), the normal block two, a cube only by one right beside it. A raised wall under a lying tall block's middle blocks the roll (the user's call: the wall stands two tiles high), while its middle may still hang over a gap. A star (extra-heavy) switch moves walls like any switch. Walls now mix with everything but hedges.
- *Not settled:* a level mixing hedges with anything but the basics, or hedges with anything but the basics, fails validation, until each world first uses them.

**One-trick guard:** every Frost level's optimal solution must use ice in at least two
distinct ways. Checked with the solver before a level reaches playtest. The ways:
*slide*; *grip* (rest standing on ice); *anchor* (a roll that stops lying half on ice);
*slide→belt* (a slide ends fully on conveyors, which push); *belt→slide* (a push onto ice
that slides on); *slide→switch* (a slide comes to rest on a switch). A lengthwise slide
always ends half on ice, so that alone doesn't count as an anchor.

**Launch pads** (Windy Peaks; **rules frozen** 2026-10-31 after the second lab playtest):
- *Trigger:* a pad fires when the block comes to rest standing on it, or lying fully on two
  pads with the same arrow (mixed arrows don't fire, like belts). Lying half on a pad is safe:
  an *anchor*. Pads are solid floor otherwise.
- *Flight:* along the arrow, over everything. The landing's nearest cell is **4** tiles past
  the block's leading edge for a standing *fling* and **2** for a lying *hop*. Mechanically:
  fly N−1 tiles, then tip once with an ordinary roll in the flight direction, so a standing
  block lands lying along the flight line, a block lying along it lands standing, and one
  lying across stays lying across.
- *Landing:* checked like any resting spot: over empty space → fall; standing on fragile →
  break; switches press; standing on the goal wins. Landing on pads that fire chains another
  flight; each pad fires at most once per move (no loops).
- *Belts* (added after the first lab playtest): after the roll and any ice slide, belts and
  pads act wherever the block rests until neither does. One belt push per move, even after a
  landing; a push onto pads fires them. A landing never slides on ice (ice stays in Frost).
- *Readability:* subtle landing marks on every cell a flight can land on, computed from the
  rules. They show where, not in what pose.
- *One-trick guard* (`signature: pads`): the optimal solution uses pads in at least two
  distinct ways: *fling*, *hop*, *chain* (2+ flights in one move), *flight→switch* (a
  landing presses a switch), *flight→goal* (a landing wins), *anchor* (rest lying half on a
  pad), *belt→pad* (a push delivers the block onto pads that fire), *flight→belt* (a landing
  gets pushed). Teaching levels opt out with `guard: off`.

**World 7: the Chasm** (dark tiles + lights + splitting), settled in a grilling session 2026-11-23; nothing is built yet. Working name; the world's name comes later.

- **Feel:** seeing and remembering, which none of the six worlds does. The user studies lit tiles, then crosses them from memory.
- **Dark tiles:** solid, but fully invisible while unlit; nothing shows until the block is on one. The rules treat them as floor, so the solver ignores lighting.
- **Lights, two kinds** ("a mix of press and hold would be cool"): a **held** light switch lights its dark tiles only while a block rests on it; a **press** light switch lights them for N moves, the number shown on the switch, then they fade. The timer counts every roll of either cube; Tab is free. It is presentation only (what's solvable never changes), so it doesn't break the 2026-11-04 rule against counting mechanics.
- **Held switches** are their own feature, usable with walls, bridges and rings too, not only lights.
- **Splitting** carries over from Splatter Studio (frozen rules), because holding needs a second cube.
- **Forcing a dark crossing** (otherwise one cube holds the light and the other walks across it lit): the whole block must cross (look while a cube holds, then join and cross in the dark), or the holder is needed elsewhere, so the path goes dark before the other cube crosses.
- **A fall in the dark rewinds** to the moment the lights last went out (usually the holder stepping off, or a timer ending), so probing (fall, undo, try the next tile) costs the walk back from the switch and memory beats guessing. It applies to a fall next to a dark tile while it's unlit; ordinary falls undo one move as everywhere else. Claude first offered restarting the level, the user picked it, then asked why, since no level does that; rewind settled it. Plain undo is the fallback if the rewind feels unfair in the lab.
- **Hint key (H)** shows the dark tiles: the player chooses to look.
- **Biome: a bottomless chasm.** Crumbling stone pillars over a pit with no bottom, mist rising from below, will-o'-wisps as the lights; the dark tiles hang over nothing. Deep sea was ruled out by the user; Starfall already owns the night sky.
- **Scope:** a lab (held switches on walls, timed lights, the dark-fall rewind, splitting in the dark), rules frozen after the user signs off, then 20 levels in batches of five.
- **Staging (the user's flow, 2026-11-24):** `01`…`05` introduce the new pieces (held lights, held switches with walls and bridges, a forgiving timed light); `06`…`10` get harder, with gravity flips and approved features from the other worlds; `11`…`15` are challenging, building on those; `16`…`20` very hard, the last the hardest. From the lab playtest: held switches and held lights early, where the player decides when the light goes out; long timed crossings (First Light's 10 dark moves) only in the hard half.
- **Batch 1 pitch** (2026-11-24, taken under that flow): `01` Lantern Rest (one block resting half on a held light, study, roll off, cross in the dark), `02` Bridge Keeper (held switches with bridges: each cube holds the bridge for the other, then the joined block crosses a path seen from the start), `03` Two Lanterns (two held light colors, one path whose colors alternate, both seen only with a cube on each), `04` Second Wind (a generous timed light with a loop back to press it again), `05` Keeper's Gate (a held light and a held gate across the chasm, the cubes trading roles).
- **Success:** no frustration (a rewind feels like your own slip, never a cheap trick), a look unlike the other six, a finale as hard as Wet Paint felt. Assumed as well: each level has a moment where memory matters.
- **Tools:** since par can't measure memory, `analyze` and `make` report the best route's steps and turns in the dark (with lighting modeled), and `lint` flags dark tiles the route crosses lit anyway.
- **Risks:** the solver can't judge how hard a level is to remember, so playtests weigh more; dark paths that are short or straight make memory trivial.
- **Starfall's gravity flip** (settled 2026-11-24, the user took Claude's pick): flips come **without splitters**, with timed lights only (one block can't hold a light and cross). A light on one floor can light dark tiles on the other: study from one floor, flip, cross in the dark. Splitting across floors (Tab, joining and the camera on two floors) stays out; a lab of its own if a later world needs it.
- **Lab rules settled in the pitch** (2026-11-24, all Claude's picks, "go with your recommendations"): a second press of a timed light **restarts** its count at N (no banking light); a dark tile shows only **while a block rests on it**, then fades (tiles never stay revealed); **anything holds** a held switch (a cube, either half of a lying block, a standing block); **one kind per color** (a color's switches are all press or all held, and a light color is never also a wall color in the same level); dark tiles carry a **light color** like walls, so two lights can light two paths.
- **Set aside for later worlds:** the countdown bomb, floor that vanishes under you, cube currents, fillable lava (all in the *Idea backlog* with their settled rules).

## Architecture

```
src/game/      pure logic (no Three.js): types, rules, solver, generator, RNG
src/levels/    handmade levels: one <chapter>.txt per chapter (format in format.ts),
               index.ts lists chapters in play order, validate.ts checks them
src/levels-page.ts  levels.html: level index with mini-maps, validation, play links
scripts/       check-levels.ts (npm run levels:check); design/ level-design tools (see CLAUDE.md)
src/render/    Three.js scene: tiles, block roll animation, camera
src/ui/        HUD, panels, persistence (localStorage)
src/worker.ts  runs the generator off the main thread
tests/         rules, solver, generator determinism, chapter format, handmade levels valid
```

- **State:** block `(x, y, orientation)` + bridge bitmask. Orientation: standing,
  lying along x, lying along y.
- **Solver:** BFS over states; returns the optimal move list. Used for par/stars,
  generator scoring, level validation, and future hints.
- **Generator:** seeded RNG → random overlapping island rectangles → hill-climb
  mutations (add/remove tiles, fragile, move start/goal, place switches & bridges),
  scored by solution length within a tier band, detours, switch presses, and
  narrow steps. Fixed iteration counts (never time-based), so a seed always gives
  the same level for a given generator version.

## Controls

Arrows/WASD move · Q/E rotate camera · Z undo · R restart · N next level · Esc or M menu

On the map: ←/→ or H/L level · ↑/↓ or J/K island · Enter play · Esc or M back

In a menu: ↑/↓ or J/K choose · Enter select · Esc or M back

## Open risks

- **Ice is one-trick** (top pre-mortem): each ice puzzle has one "aha" and is dull once
  solved. Guarded by the two-decision rule; watch for it in playtest notes.
- **Unreadable slides:** players can't predict where a slide ends. May need a slide-path
  hint; the ice lab should show whether it does. Settings now offers a slide-end preview, off by default (2026-11-20).
- Generated levels feel bland → compare against the reference levels; tune scoring.
  Generated shapes stay rectangular until archipelago generation lands.
- "Handmade levels improve the generator" has no concrete method yet; design it with
  the climb.
- Splitting may be very hard to generate well.
- "Beats the original" has no concrete test yet; judged by feel.
- **Pads are just bridges** (Windy Peaks pre-mortem): once you know where a pad goes, the
  level is done. Guarded by the two-uses rule and the three depth sources.
- **Landing pose unreadable:** marks show where a flight lands, not how. Watch for it in the
  lab playtest.
- **Long flights leave the frame** or read as random; chains stayed in frame in both lab rounds.
  Very long levels still shrink when rotated so their long side runs into the screen.
- Seed links break when the generator changes. Full-level links fix this.

## Running

```
npm install
npm run dev      # play at the printed localhost URL
npm test         # rules, solver, generator, reference levels
npm run levels   # print sample generated levels as text
npm run levels:check   # validate handmade levels (add -- --fill-par to record new pars)
                 # level index: /levels.html on the dev server; play one: /?level=<id>
npm run build    # static site in dist/ for GitHub Pages / itch.io
```
