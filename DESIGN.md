# Skytumble — Design

An original rolling-block puzzle game: tip a 1×1×2 block across floating sky islands
and drop it upright into the goal hole. Levels are procedurally generated and verified
by a solver. Inspired by the rolling-block genre; its own name, look, and levels.

## Goals

- Built for fun: a game I play myself and introduce to friends.
- Improve on the classic genre: generated levels, scoring against the optimal solution,
  a better camera.
- Stop feeling like a copy. v1 matched the classic games in mechanics, level shapes, and
  loop; all three need to become Skytumble's own.

**Success (six months out):** I still play it; friends come back to it unprompted; side
by side it feels better than the old games; the project keeps growing.

**A new mechanic succeeded** if I choose levels that feature it unprompted, weeks later.

## Decisions

| Area | Decision | Why |
|---|---|---|
| Identity | Original game, **Skytumble**; floating islands, in the sky at first and anywhere later | Own look and name; not a clone |
| Visuals | 3D (Three.js). All art made in code, no model packs (decided 2026-11-01) | One consistent style, nothing to download |
| Platform | Desktop only, keyboard | — |
| Camera | Rotates in 90° snaps; controls are screen-relative (Up = away from you) | No ambiguous diagonals |
| Timing | Turn-based only; anything "timed" counts moves, not seconds | Solver stays exact; par stays meaningful |
| Organization | **Themed biomes** replace difficulty tiers. Each biome starts with one signature mechanic; later biomes mix earlier ones | Gives mechanics a home and an identity |
| Base layer | Floor, fragile, switches, bridges appear in every biome; they are not a biome | They're the grammar every biome builds on |
| Difficulty | Rises with depth: further into a biome, higher in the climb | No separate tier picker |
| Level shapes | Archipelagos: several small islands joined by crossings | Rectangle blobs read as the old games |
| Crossings | Bridges now; teleporters, launch pads, drops/elevators later | Keep each release to 1–2 new mechanics |
| Pace | 1–2 new mechanics per release, each done deeply | Depth over a grab bag |
| Rule changes | Prototype new rules in throwaway "lab" levels; rules freeze after playtest sign-off | Rewriting rules breaks handmade levels |
| Quality guard | ~5 handmade reference levels to judge generator output against | Pre-mortem: "generated levels feel bland" |
| Sharing | Seed links (`?tier=…&seed=…`); old links may change as the generator evolves | Links mean "play this now" |
| Hosting | Static site (GitHub Pages / itch.io), no accounts | Free, nothing to run |
| Tech | Vite + TypeScript + Three.js; generator/solver in a Web Worker | Type safety for logic; UI never freezes |

**"Hard" means:** precise orientation, switch logic, deceptive layouts (routes that
detour away from the goal). Solution length alone is not the target.

## Modes

| Mode | Purpose | Levels | Failure |
|---|---|---|---|
| **Campaign** | Learn: the natural progression for getting better | Handmade, one chapter per biome | Undo always allowed |
| **Endless climb** | Test: the replayable challenge | Generated; altitude bands are biomes | No undo; a fall ends the run; score = altitude |
| Quick play (v1) | Kept until the climb replaces it | Generated by tier + seed | Undo allowed |

- **Map:** a sky map of biome islands, all open from the start with a suggested path
  (soft order) so friends can jump anywhere.
- **Daily climb:** everyone gets the same run seed each day (derived from the date in the
  browser, no server); friends compare altitudes.
- **Handmade → generated:** campaign levels show what good levels in each biome look
  like; the generator learns each biome from them when the climb is built.

## Mechanics

| Mechanic | Rule |
|---|---|
| Rolling | Block is standing (1×1) or lying (1×2); rolling tips it over an edge |
| Goal | Win by standing upright on the goal; lying across it is safe |
| Falling | Any part of the block over empty space → fall |
| Fragile tile | Breaks if the block stands upright on it |
| Soft switch | Toggles its bridge group when any part of the block lands on it |
| Heavy switch | Toggles its bridge group only when the block stands on it |
| Bridge | Solid only while its group is on |
| **Ice** (Frost) | A lying block fully on ice slides in the roll direction; a standing block grips |
| **Conveyor** (Frost) | After a move, a block fully on conveyors shifts one tile along the arrow |
| **Launch pad** (Windy Peaks) | Flings the block along the pad's arrow: standing = long fling, lying fully on two same-arrow pads = short hop |
| **Flip tile** (Starfall) | Standing on one, or lying fully on two, moves the block to the other floor directly above (or below), same pose |

**Whole-block rule:** a special tile (ice, conveyor) acts only when the entire block is on
it. A lying block half on ice and half on floor does not slide. A lying block on two conveyors
pointing different ways is not pushed.

**Move resolution:** roll → slide while fully on ice → the slide stops as soon as any part
leaves ice → the tile it rests on acts (a conveyor pushes once per move; if that leaves a
lying block fully on ice, it slides in the push direction) → stop. Falls are checked at
every step. Only resting spots trigger fragile tiles and switches; tiles passed mid-slide
don't. One conveyor push per move means no infinite loops.

**One-trick guard:** every Frost level's optimal solution must use ice in at least two
distinct ways. Checked with the solver before a level reaches playtest. The ways:
*slide*; *grip* (rest standing on ice); *anchor* (a roll that stops lying half on ice);
*slide→belt* (a slide ends fully on conveyors, which push); *belt→slide* (a push onto ice
that slides on); *slide→switch* (a slide comes to rest on a switch). A lengthwise slide
always ends half on ice, so that alone doesn't count as an anchor.

**Launch pads** (Windy Peaks; **rules frozen** 2026-10-31 after the second lab playtest):
- *Trigger:* a pad fires when the block comes to rest standing on it, or lying fully on two
  pads with the same arrow (mixed arrows don't fire, like belts). Lying half on a pad is safe:
  an *anchor*. Pads are solid floor otherwise.
- *Flight:* along the arrow, over everything. The landing's nearest cell is **4** tiles past
  the block's leading edge for a standing *fling* and **2** for a lying *hop*. Mechanically:
  fly N−1 tiles, then tip once with an ordinary roll in the flight direction, so a standing
  block lands lying along the flight line, a block lying along it lands standing, and one
  lying across stays lying across.
- *Landing:* checked like any resting spot: over empty space → fall; standing on fragile →
  break; switches press; standing on the goal wins. Landing on pads that fire chains another
  flight; each pad fires at most once per move (no loops).
- *Belts* (added after the first lab playtest): after the roll and any ice slide, belts and
  pads act wherever the block rests until neither does. One belt push per move, even after a
  landing; a push onto pads fires them. A landing never slides on ice (ice stays in Frost).
- *Readability:* subtle landing marks on every cell a flight can land on, computed from the
  rules. They show where, not in what pose.
- *One-trick guard* (`signature: pads`): the optimal solution uses pads in at least two
  distinct ways: *fling*, *hop*, *chain* (2+ flights in one move), *flight→switch* (a
  landing presses a switch), *flight→goal* (a landing wins), *anchor* (rest lying half on a
  pad), *belt→pad* (a push delivers the block onto pads that fire), *flight→belt* (a landing
  gets pushed). Teaching levels opt out with `guard: off`.

### Idea backlog

Wanted, not yet scheduled. Each becomes a biome's signature mechanic or a crossing.

- **Desert biome look (from the first Windy Peaks build, which the user liked as a desert):** warm
  layered sandstone spires (`0xe2bd85` / `0xa98a70`) in golden haze (`0xf5e0b2`), gold-lit cumulus,
  blowing golden grit, and a parchment ivory block (`0xe6cf9f`). These colors and `src/render/peaks.ts`'s
  spires are enough to rebuild it.
- **Future worlds (from the user, 2026-11-02, for the late future):** ocean, desert, lava, dark abyss, factory, cave and others. These are why *Worlds* in the shared theme rules no longer requires a sky.
- **Tiles:** teleporters, crumbling/timed tiles
- **Momentum pads:** fling the block onward in the direction it rolled onto the pad (deferred
  from Windy Peaks to keep one pad kind per chapter)
- **Block changes:** grow/shrink (1×1×3, 1×1×1 cube; goal needs a size), paint (color
  gates), split into two cubes, fuse with a second block into a new shape
- **Vertical:** drop-down to lower islands, 1-tile ledges (standing block tips up),
  elevators, goal on a lower layer
- **World rules:** tilting islands that tip under the block's weight
- **Switch-driven conveyors:** a switch reverses (or turns) a set of belts — from the ice
  lab playtest

**Next release — Starfall** (gravity flip), planned in a grilling session 2026-11-01:

- *Goal:* "two worlds": holding two maps in your head, where a hole below is floor above.
  Success = it beats Windy Peaks as my favorite chapter, through spectacle; the spectacle
  comes from the look (a starfall night), not from long animations.
- *Why gravity:* the user's own vision for the next biome. Shape-changing blocks (grow/shrink,
  split) wait for the biome after; a later chapter may cross the two.
- *Scope:* same as Windy Peaks: camera prototype, a ~6-level lab, ~8 handmade levels, a map
  island. Mix: base layer, pads, belts. Not in scope: generator, editor, sound, ice, shape
  change. No time pressure; the user is the only player. Deep core changes are fine.
- *Rules* (**frozen** 2026-11-01 after the gravity lab playtest: "it does feel predictable now"):
  - Every level may have a **ceiling layer** directly above the ground, same coordinates.
  - **Flip tiles** fire like pads: resting standing on one, or lying fully on two; lying half
    on one is safe. A flip moves the block to the other layer **directly above (or below), in
    the same pose**. Each layer has its own flip tiles. A flip never re-fires in the same move.
  - Nothing on the other side → the block **falls into the sky**. Rolling off a ceiling edge
    or breaking a ceiling fragile tile does the same.
  - Flips join the belt/pad chain: a push or a flight that rests the block on flip tiles flips it.
  - Pads fling within the current layer. Switch groups are shared: a switch on one layer can
    drive bridges on the other.
  - The goal can be on either layer.
  - *One-trick guard* (`signature: gravity`): two distinct flip uses among flip up, flip down,
    lying flip, belt→flip, flight→flip, cross-layer press.
- *Depth:* round trips (go up, change something, come back down), hole alignment, cross-layer
  switches, pose setup for the flip.
- *Feel:* flips of about 0.8s (changed from ~0.5s in the Starfall theme grilling, 2026-11-02). Controls stay screen-relative (as with Q/E rotation). A
  **hold-to-peek** key swings the camera over to look at the other layer.
- *Pre-mortem:* "disorienting and unreadable". The turning camera mirrors the ceiling relative
  to the ground, which works against two-worlds mapping. Hence the prototype first.
- *Theme:* starfall night: dark blue sky, stars, glowing flip tiles. Name: **Starfall**.

**Next release — Toybox** (shape-changing blocks), planned in a grilling session 2026-11-01:

- *Goal:* "right shape here": a gap only a long block spans, a spot only a cube can use.
  Success = a fresh rhythm: long stretches where you move differently, not one-step detours.
- *Scope:* the **cube (1×1×1)** and the **tall block (1×1×3)**. Split and paint were cut to the
  following biome (scope challenge: four shapes in eight levels would each be taught and dropped).
  Mix: base layer and belts only (pads, flips, ice stay in their chapters). Same process as
  Starfall minus the camera prototype: rules, solver, and animations with tests → a ~6-level
  lab → playtest → rules freeze → 8 levels and a map island. No rush; the user is the only player.
- *Rules* (**frozen** 2026-11-01: the user went on to the chapter after the shape lab with no rule notes):
  - **Shape switches** set the block's shape when it **stands** on them (lying across is safe):
    cube, tall, and a **normal** switch to turn back. A shape change happens where you stand, so
    it always fits.
  - Levels may **start** you in any shape.
  - **Cube:** rolls one tile at a time, always standing; **light**: never breaks fragile tiles,
    never presses heavy switches (soft switches yes).
  - **Tall:** tips three tiles at a time; lying, it rests on its **two ends**, so it **spans a
    one-tile gap** (and, lying across two parallel rails, can roll along the gap between them); breaks fragile tiles only standing (like normal); **extra-heavy switches**
    respond only to a standing tall block.
  - **Goal:** normal standing by default; a goal can be **marked** for a cube or a tall block.
  - Belts follow the whole-block rule (a lying tall block moves only if all three tiles are belts).
  - *One-trick guard* (`signature: shapes`): two distinct shape uses among become cube, become tall,
    back to normal, cube crosses fragile, tall spans a gap, tall presses an extra-heavy switch,
    shaped goal.
- *Readability from day one:* each shape switch shows a small model of its shape; a shaped goal's
  marker takes that shape.
- *Pre-mortem:* too many rules, same rhythm, unreadable (and fiddly split, now deferred).
- *Theme:* toy blocks in a sky playroom. Name: **Toybox**.
- *Kept for the split/paint biome:* a swap key steers one cube at a time; cubes merge on touch and
  must merge before the goal; wrong-color gates are walls (pushing into one does nothing, no move
  counted); each split cube can carry its own color.

**Next release — chapter themes**, shared rules settled in a grilling session 2026-11-01. New
levels wait until this is done. Themes only change how levels are drawn; rules, pars and
solutions don't change.

- **Main job:** the world explains the mechanics (ice is slippery because this place is frozen).
- **Biggest risk:** puzzles getting harder to read. Clarity beats decoration, always.

| Area | Rule |
|---|---|
| Worlds | Distinct palette, lighting, surroundings and materials per chapter. A world can be any place (widened 2026-11-02, was "still floating in the sky"): the board's tiles still float over open space, so a gap always reads as a fall |
| Scenery | Far backdrops, things hanging under tiles, flat tile details. No nearby islets |
| Below the board | Treetops or summits may rise from below if they stop under board level and fade into haze, so gaps still read as empty |
| Floor tiles | Same cubes, new color and material. Detail on most tiles, in shades of the floor's one color |
| Mechanics and goal | Same shape and color coding in every chapter, with a themed finish: an ice tile stays recognizable wherever chapters mix |
| Outlines | A subtle rim on colored switches and bridges in every world, to solve color clashes consistently |
| Block | Same block, tinted per chapter |
| Motion | Gentle ambience: slow swaying and light drifting particles |
| Interface | Accent colors only. Sky map islands match each world's colors |

## Architecture

```
src/game/      pure logic (no Three.js): types, rules, solver, generator, RNG
src/levels/    handmade levels: one <chapter>.txt per chapter (format in format.ts),
               index.ts lists chapters in play order, validate.ts checks them
src/levels-page.ts  levels.html: level index with mini-maps, validation, play links
scripts/       check-levels.ts (npm run levels:check); design/ level-design tools (see CLAUDE.md)
src/render/    Three.js scene: tiles, block roll animation, camera
src/ui/        HUD, panels, persistence (localStorage)
src/worker.ts  runs the generator off the main thread
tests/         rules, solver, generator determinism, chapter format, handmade levels valid
```

- **State:** block `(x, y, orientation)` + bridge bitmask. Orientation: standing,
  lying along x, lying along y.
- **Solver:** BFS over states; returns the optimal move list. Used for par/stars,
  generator scoring, level validation, and future hints.
- **Generator:** seeded RNG → random overlapping island rectangles → hill-climb
  mutations (add/remove tiles, fragile, move start/goal, place switches & bridges),
  scored by solution length within a tier band, detours, switch presses, and
  narrow steps. Fixed iteration counts (never time-based), so a seed always gives
  the same level for a given generator version.

## Controls

Arrows/WASD move · Q/E rotate camera · Z undo · R restart · N next level · L sky map

On the map: ←/→ level · ↑/↓ island · Enter play · Esc/L back to the level

## Open risks

- **Ice is one-trick** (top pre-mortem): each ice puzzle has one "aha" and is dull once
  solved. Guarded by the two-decision rule; watch for it in playtest notes.
- **Unreadable slides:** players can't predict where a slide ends. May need a slide-path
  hint; the ice lab should show whether it does.
- Generated levels feel bland → compare against the reference levels; tune scoring.
  Generated shapes stay rectangular until archipelago generation lands.
- "Handmade levels improve the generator" has no concrete method yet; design it with
  the climb.
- Splitting may be very hard to generate well.
- "Beats the original" has no concrete test yet; judged by feel.
- **Pads are just bridges** (Windy Peaks pre-mortem): once you know where a pad goes, the
  level is done. Guarded by the two-uses rule and the three depth sources.
- **Landing pose unreadable:** marks show where a flight lands, not how. Watch for it in the
  lab playtest.
- **Long flights leave the frame** or read as random; chains stayed in frame in both lab rounds.
  Very long levels still shrink when rotated so their long side runs into the screen.
- Seed links break when the generator changes. Full-level links fix this.
